# コピー＆ペースト

コピー＆ペーストは列定義に以下の属性を指定することで有効になります。
（セル編集を有効にするためのプロパティと同じもの）

* `toText`
  * その列のセルからクリップボードへコピーする文字列を返します。
  * 未指定の場合、その列のセルからのコピーは空文字になります。
* `fromText`
  * クリップボードの文字列を反映した新しい行オブジェクトを返します。
  * 未指定の場合はその列でペーストしても何も起きなくなります。

貼り付けた結果は、何セル貼り付けても**1回の貼り付けにつき1回だけ**、変更のあった行をまとめて
グリッドの `onRowsChange` に渡されます。React Hook Form の `setValue` のように1回ごとのコストが高い反映先でも、
呼び出し回数はセルの数ではなく行の数で済みます。

クリップボードとの間ではTSV（タブ区切りテキスト）でやり取りするため、
Excelやスプレッドシートソフトとの間でもそのまま貼り付け合うことができます。

以下の例では、グリッドをクリックしてフォーカスした状態で、範囲選択 → `Ctrl + C` / `Ctrl + V` が使えます。
また、範囲選択して Delete キーを押すと、読み取り専用セルを除いて空になります。

グリッド自体はクリップボードとの間で文字列をそのまま受け渡すだけで、型変換・妥当性検証は一切行いません。
文字列との変換ロジックは、各項目の仕様に合わせて `toText` / `fromText` に自由に定義することができます。
`fromText` で文字列を解釈できない場合は `undefined` を返すと、そのセルだけ書き込まれずに元の値が保たれます。
キーボード入力やIMEを経由しない任意の文字列（他アプリからの貼り付けを含む）が渡ってくる前提で、
防御的に実装する必要がある点に注意してください。

## 対応している操作

グリッドにフォーカスが当たっている状態で、以下のキー操作に対応しています。

* `Ctrl + C`（コピー）: 選択範囲のセルの値をタブ区切りでクリップボードへ書き込む
* `Ctrl + V`（ペースト）: クリップボードの内容を選択範囲へ書き込む
* `Delete`: 選択範囲のセルの値を空文字にする（ペーストにおける「空文字を貼り付けた」場合と同じ経路で処理される）

**切り取り（`Ctrl + X`）には対応していません。** セルエディタでの編集中は、
これらのキー操作はグリッド側では処理されず、ブラウザ標準のテキストコピペとして
セルエディタ（`<textarea>` 等）に委ねられます。

## コピーペースト処理詳細

コピーペースト処理のロジックは自由にカスタマイズ可能です。

以降では既定のロジックとカスタマイズ方法の両方を説明します。

### 既定の仕様

貼り付け先の範囲は、ペースト時点の選択状態によって決まります。

* **1セルだけを選択している場合**：貼り付ける内容のサイズに合わせて選択範囲が自動的に拡張され、
  貼り付け後はその拡張後の範囲が選択された状態になります。
  （例：2行2列のデータをコピーし、1セルを選択してペーストすると、貼り付け後は2行2列が選択される）
* **複数セルの範囲を選択している場合**：選択範囲は広がらず、貼り付ける内容が範囲内に
  繰り返し敷き詰められます（内部的には行・列とも剰余で折り返して埋めています）。
  1セルだけコピーして広い範囲に貼り付けると、その値で範囲全体を埋められます。

どちらの場合も、**グリッドの外へははみ出しません。** 行数・列数を超えた分のデータは
そのまま破棄され、**ペーストによって行が新しく追加されることはありません。**
行を増やしたい場合は、あらかじめ利用側で行を追加してからペーストしてください。

```
1セル選択時：クリップボードのサイズ（2行2列）に選択範囲が拡張される
  選択前              貼り付け後
  [■][ ][ ]           [■][■][ ]
  [ ][ ][ ]      →    [■][■][ ]
  [ ][ ][ ]           [ ][ ][ ]

範囲選択時：クリップボードの内容（1行2列）が選択範囲（2行4列）に敷き詰められる
  選択範囲             貼り付け後（A,Bが繰り返し敷き詰められる）
  [■][■][■][■]        [A][B][A][B]
  [■][■][■][■]   →    [A][B][A][B]
```

---

読み取り専用のセルは、ペースト時に**その1セルだけがスキップ**されます。
選択範囲の一部に読み取り専用のセルが含まれていてもペースト処理全体が
キャンセルされることはなく、書き込み可能なセルにだけ値が反映されます。
`Delete` による範囲クリアでも同様に、読み取り専用セルだけが変更されずに残ります。

読み取り専用かどうかは、以下のいずれかに該当するかで判定されます。

* グリッド全体の `isReadOnly` が `true`、または行を受け取って `true` を返す関数である
* 列定義の `isReadOnly` が `true`、または行を受け取って `true` を返す関数である

なお、**コピーは読み取り専用のセルに対しても可能**です（`toText` さえ
定義されていればよい）。上記デモの「金額」列は `isReadOnly: true` かつ
`fromText` 未定義の計算列で、値をコピーすることはできますが、
どんな内容をペーストしても変化しません。

---

クリップボードとのやり取りには、以下の仕様のTSV（タブ区切りテキスト）を使用します。

* セルの区切りはタブ文字、行の区切りは **CRLF**（Excelへの貼り付けを想定した改行コード）
* セルの値に `"`（ダブルクォート）または改行を含む場合は、そのセル全体を `"` で囲み、
  内側の `"` は `""` に二重化してエスケープする
* 読み込み時はまず `CRLF` を `LF` に正規化してからパースするため、改行コードが
  混在していても問題なく処理できる

この仕様はExcelがクリップボードにコピーする形式と互換なので、上記デモの「備考」列のように
セル内改行を含む値であっても、Excelとの間でそのまま相互にコピペできます。

### コピーペースト処理のカスタマイズ

列定義に以下の2つのプロパティを指定することで、それぞれ差し替えることができます。

* `clipboardFormat`
  * クリップボードとやり取りする文字列の形式の定義
* `planPaste`
  * 貼り付け・Deleteキーによるクリア時に「どのセルに何を書き込むか」を決める関数。
  * グリッドの状態を直接変更しない純粋関数。この関数自体の役割は、
    どのセルをどう書き換えるかの情報を持った配列 `writes` を返すまでであり、
    実際のセルへの書き込みや選択範囲の更新は、戻り値を受け取ったグリッド側が行います。
  * `writes` に含まれていても、グリッドの外のセルや、読み取り専用のセルには書き込まれません。
    特定のセルが書き込み可能かは引数の `isCellWritable` を使うと `planPaste` 内部でも調べられます。
  * ペーストによって行が新しく追加されることはありません。
  * 戻り値の `nextSelectedRange` を指定すると、ペースト完了後にグリッドの選択範囲が変わります。
    なお、 `nextSelectedRange` がグリッドの外にはみ出していても、グリッド内に収まるよう調整されます。

**例：既定の結果をラップして一部だけ変える。**
1セル選択時の範囲拡張はそのまま使い、拡張後の選択範囲だけ変えたくない場合。

```ts
const planPaste: EditableGrid2PastePlanner = args => {
  const plan = defaultPastePlanner(args)
  return { ...plan, nextSelectedRange: undefined }
}
```

**例：`isCellWritable` を使い、読み取り専用セルが1つでも含まれていたら貼り付け全体を中止する。**
既定の実装は書き込み不可のセルだけをスキップしますが、業務要件によっては
「一部でも書き込めないなら失敗として扱いたい」というケースもあります。

```ts
const planPaste: EditableGrid2PastePlanner = args => {
  const { selectedRange, isCellWritable } = args
  for (let r = selectedRange.startRow; r <= selectedRange.endRow; r++) {
    for (let c = selectedRange.startCol; c <= selectedRange.endCol; c++) {
      if (!isCellWritable(r, c)) return { writes: [] } // 何も書き込まずに中止
    }
  }
  return defaultPastePlanner(args)
}
```

なお、`Delete` キーによるクリアも `planPaste`（`trigger: 'delete'`、`values: [['']]`）を通るため、
上記のような方針変更は Delete の挙動にも及びます。Delete だけ既定の挙動のままにしたい場合は
`trigger` で分岐し、`'delete'` のときは `defaultPastePlanner` にそのまま委譲してください。
