# セル単位のエラー表示

セル単位のエラー表示のための専用の仕組みはありません。

エラー情報を state などに保持しておき、 `renderBody` でそれを受け取って表示すれば可能です。
エラー情報は以下いずれかの方法で受け取れます。

* `getValuesForRender` でセルの値だけでなくエラー情報も返すようにする（推奨）
* `renderBody` 内部でセルの値を受け取るReactフックを使う

## renderBody でエラーを表示する（getValuesForRender経由）

セルは `getValuesForRender` の戻り値が変わったときに描画し直されます。
エラーメッセージをこの配列に含めれば、そのままレンダリングに使えます。

<Source language="tsx" code={`
  col.leaf({
    columnId: "name",
    getValuesForRender: (row) => [row.name, getCellError(row, "name")], // getCellError の実装内容は自由
    renderBody: ({ deps: [name, error] }) => <CellText error={error}>{name}</CellText>,
    ...
  })
`} />

なお `getValuesForRender` は描画中のセルの数だけ呼ばれます。
エラーの一覧を毎回線形探索すると行数×列数のコストがかかるため、
上記デモのように「行のキー → 列ID → メッセージ」の形に索引を作っておいてください。

## renderBody でエラーを表示する（Reactフック経由）

`renderBody` はセルごとに独立したコンポーネントとして描画されるため、内部でフックを呼び出せます。
エラーの購読をセル単位で行いたい場合はこの性質を使えます。

<Source language="tsx" code={`
  renderBody: ({ deps: [name], rowKey }) => <NameCell name={name} rowKey={rowKey} />,

  // ...

  function NameCell({ name, rowKey }: { name?: string, rowKey: string }) {
    const error = useCellError(rowKey, "name") // 自分のセルのエラーだけを購読する
    return <CellText error={error}>{name}</CellText>
  }
`} />

ただし、表示中のセルの数だけ購読が張られること、
フックのルール通り呼び出し順が毎回同じでなければならないことに注意してください。
`getValuesForRender` の deps で足りる場合はそちらの方が単純です。

## zod との組み合わせ

`zod` などのスキーマ検証ライブラリを使う場合も、考え方は同じです。
スキーマの検証結果を「列ID → メッセージ」の形に変換し、`getValuesForRender` から引くだけです。

<Source language="ts" code={`
  const rowSchema = z.object({
    name: z.string().min(1, "商品名を入力してください。").max(10, "商品名は10文字以内で入力してください。"),
    quantity: z.number("数量を入力してください。").int().positive("数量は1以上の整数で入力してください。"),
    unitPrice: z.number("単価を入力してください。").nonnegative("単価に負の数は指定できません。"),
  })

  /** 1行分の検証結果を「列ID → メッセージ」にする。列IDとプロパティ名を一致させておくと単純に済む。 */
  function validateRow(row: Row): Partial<Record<string, string>> {
    const result = rowSchema.safeParse(row)
    if (result.success) return {}

    const errors: Partial<Record<string, string>> = {}
    for (const issue of result.error.issues) {
      const columnId = String(issue.path[0])
      errors[columnId] ??= issue.message // 同じ項目に複数の指摘がある場合は先頭だけ表示する
    }
    return errors
  }
`} />

上記デモのように検証結果を state に保持する場合、`validateRow` が呼ばれるのは
検証のタイミング（画面初期表示時・セル編集時・送信時）だけなので、コストは問題になりません。
一方、保持せず `getValuesForRender` の中で毎回検証する場合は `validateRow` がセルの数だけ呼ばれ、
行数の多いグリッドでは無視できないコストになります。
その場合は列ごとに必要な部分だけを検証するか、行のキーごとに結果をキャッシュしてください。

<Source language="ts" code={`
  // 行オブジェクトをキーにしたキャッシュ。
  // textToCell が行のディープクローンを返す（＝値が変わると別のオブジェクトになる）ことを利用して、
  // 値が変わっていない行の検証結果を使い回す。
  const cache = new WeakMap<Row, Partial<Record<string, string>>>()

  function validateRowCached(row: Row) {
    let result = cache.get(row)
    if (!result) {
      result = validateRow(row)
      cache.set(row, result)
    }
    return result
  }
`} />

React Hook Form の `resolver` にスキーマを渡している場合は、
`formState.errors` をそのままエラーの持ち主として使うこともできます。
その場合、エラーは React Hook Form が行の並びに追従させてくれますが、
`formState.errors` の変化はグリッドの `subscribe` の対象外（値の変化ではない）なので、
エラーが変わったときに列定義を作り直すなどして、セルを描画し直す経路を用意する必要があります。
