# パフォーマンス

EditableGrid2 は TanStack Virtual による仮想化を利用しデータ数が多いテーブルの処理高速化を図っています。

以下は **1万行 × 45列（45万セル）** のグリッドです。

* 12ヶ月分の月別列（計画・実績・差異）がグループ列として横方向に並びます。
* セルを編集すると、**同じ行の他の列**（差異・年間計画・年間実績・年間計画金額）へ値が波及します。
* さらに構成比・累計構成比は全行の年間計画の合計を分母に持つため、どこか1セルを編集すると**すべての行**の値が変わります。
  （構成比は1万行のうちの1セルぶんの影響なので動きがごくわずかです。他の行への波及を目で確かめるには累計構成比を見てください。）
* 上部のボタンから、**グリッドの外側**のトリガーでグリッド内の値をまとめて書き換えられます。
* 行の追加と、行頭チェックボックスによる行削除ができます。

## 値の変更と再描画

1セルを編集しても、1万行分のデータを作り直したり、表示中のすべてのセルを描き直したりはしません。

* データは React の state ではなくストア（下記の `PerfDataStore`）が保持し、グリッドには
  行の並び（`rowKeys`）・最新の値の取得関数（`getLatestRowObject`）・変更通知の購読関数（`subscribe`）を渡しています。
* 値が変わるとストアが通知し、グリッドは表示中のセルごとに列定義の `getValueForRerender` を呼び出して前回の戻り値と比較し、
  **戻り値が変わったセルだけ**を描画し直します。
  構成比のように他の行の値に依存する列でも、どのセルが影響を受けるかを利用側で管理する必要はありません。
* グリッドの操作による変更（編集確定・貼り付け・Delete）は、1回の操作につき1回だけ、行単位にまとめて `onRowsChange` に渡されます。

再描画の最適化の恩恵を最大限に受けるためには、グリッドに渡す関数
（`getLatestRowObject` / `isReadOnly` / `showCheckBox` / `getRowClassName`）の参照を
`useCallback` や `useMemo` で安定させる必要があります。
これらの参照が変わると、グリッドは判定結果が変わったかもしれないと見なして、
表示中の全セルの値を取得し直して比較をやり直します。

## 仮想スクロール

行と列の両方が仮想化されています。実際に DOM として描画されるのは、画面に見えている行・列と、その前後の少し外側（overscan）のセルだけです。

* 表示範囲外をどこまで予め描画しておくかは、行は `rowOverscan`、列は `columnOverscan` で調整できます。
  スクロール時にセルの描画が一瞬遅れて見える場合は値を大きくしてください。
* 固定列（`isFixed`）と行頭のチェックボックス列は、スクロール位置に関わらず常に描画されます。
* 表示範囲の外に出たセルはアンマウントされるため、`renderBody` の中で持っている state はスクロールで失われます。
  保持したい値はグリッドの外側（行データやストア）に持たせてください。
* 行の高さは、その行で描画中のセルの高さから測ります。
  折り返しなどで背の高いセルがある場合、横スクロールでそのセルが表示範囲に出入りすると、行の高さが変わることがあります。
  この挙動を嫌う場合は `columnOverscan` をとても大きくする、つまり常に全列レンダリングすることで回避できます。
